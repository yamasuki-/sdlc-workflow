# 工程 0: 取り込み（00-intake）

> **配置と上書き**: このスキルのディレクトリは `${CLAUDE_SKILL_DIR}`。これが `~/.claude/skills/` 配下で、
> プロジェクトに `.claude/skills/phase-intake/SKILL.md` がある場合は、そちらを Read してその指示に従い、以下は使わない
> （Claude Code は同名スキルを `~/.claude` 側で解決するため、プロジェクト版はこの方法で優先させる）。
> `<SDLC>/…` はワークフロー本体のファイル。`scripts/sdlc path <…>` で実際のパスを得てから読む。

まず `<SDLC>/phase-flow.md`（共通フロー）を読み、その型に従って進める。以下は本工程固有の内容のみ。

## 入力 / 成果物
- 入力: `input/` の要求ドキュメント（.xlsx / .xlsm / .docx / .pptx / .md）。原本も工程 0 のゲートのハッシュ対象。
- 成果物（`docs/00-intake/`）:
  - `<ファイル名>.md` … 中間形式。断片ごとに `### SRC-xxx`・出典・種別・確信度・注記・本文
  - `assets/` … 画像化した図・スライド
  - `index.md` … 取り込み結果一覧（テンプレート `intake-index.md`）
  - `plan.md` / `summary.md` / `review.md`

| 形式 | 出典の単位 | アダプタの扱い |
|---|---|---|
| Excel | シート名＋セル番地 | 結合セルを展開し、表は行単位の断片（確信度 中）。画像は抽出 |
| Word | 見出し階層＋段落番号 | 表は行単位。変更履歴の挿入=中、削除=注記。画像は抽出 |
| PowerPoint | スライド番号＋図形 | 画像・図形とコネクタで描いた構成図は画像化して「要画像読取」（確信度 低） |
| Markdown | 見出し＋行番号 | ほぼそのまま |

## 計画（plan）
1. `input/` のファイル一覧を確認する（未対応形式は人に変換を依頼）。
2. **変換は計画ステップで機械的に実行する**（エージェント不要）:
   `scripts/sdlc intake input/<ファイル> [input/...]`
   形式の追加は本体の `lib/intake/adapters/` にモジュールを足して登録するだけでよい（本体の変更なので人が行う）。
3. 変換結果の件数・確信度 低の件数・「要画像読取」の件数を plan.md に記録する。

## タスク分解（decompose） — agent: analyst
- 「要画像読取」の断片を、入力ファイル単位（多ければスライド・シート範囲単位）で 1 タスクにする。
  担当ファイル = その中間形式 `.md`（同じ .md を触るタスクは並行させない）。
- `index.md` の作成を最後のタスクにする（全タスクに依存）。

## 実行時の作業内容（タスク指示に含める）
- 図の読み取り: `assets/` の画像を Read ツールで読み、該当 SRC の本文「要画像読取」を読取結果に置き換え、
  `- 読取: 画像から読み取り` と確信度（高/中/低）を付ける。構成図は要素と関係（矢印の向き）を、権限表は表として書く。
  読み取れない部分は確信度 低のまま理由を注記する。
- **原文に無い内容を補わない**。要約・意訳もしない。
- index.md: ファイルごとの SRC 範囲・件数、確信度 低の一覧（要求整理・分析の質問リストに回す）。

## 統合・レビュー
- 原本と件数照合（シート数・スライド数・見出し数）を summary.md に記録する。
- reviewer にはチェックリスト `00-intake.md` を渡す。

## ゲートで人に確認してほしい点（例）
- 確信度 低の断片の扱い、取り込み対象外にするシート・スライド。
