# レビューチェックリスト: 不具合対応（原因判定）

1. 再現テストが不具合を再現して失敗（Red）している
2. 原因がトレース ID と該当箇所（ファイル:行）で特定され、根拠（どの成果物のどの記述が誤りか）がある
2a. 観測エビデンス（実行コマンド・ログ・値）が生のテキストで残り、推測で結論を出していない
2b. 調査のための一時計装が除去され、調査による変更が残っていない
2c. 対応方法の選択肢（ある場合）に「あるべき姿」案と「最小修正」案があり、乖離と技術的負債が比較できる
3. 混入工程が「上流から順に正しさを判定し、最初に誤りがあった工程」になっている
4. 流出工程と見逃し理由が具体的（どのレビュー観点・テストで見つけるべきだったか）
5. 影響範囲が trace impact と整合し、やり直し工程に漏れが無い
6. 作成者・レビュアーの自己弁護ではなく、成果物の記述に基づいている

## プロジェクト固有の観点

このファイルは全プロジェクト共通の本体なので編集しない。プロジェクトで追加する観点（不具合の再発防止を含む）は
`rules/review-<工程ID>.md` に書く（reviewer がこのチェックリストと合わせて確認する）。
